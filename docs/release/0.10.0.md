# Class A Bridge 0.10.0 Public Beta

This release makes the first assessment useful as a team handoff: users receive three specific tasks with owners, evidence requests, completion conditions and direct workspace navigation. The result page exports the same plan without requiring a visit to Reports or entering identifying information.

## Changes

- Finding-specific next actions replace generic class-level advice. A carve-out with no unknown answers no longer produces an uncertain-answer task.
- Non-SOC-2 starting points are described as outside this tool's SOC 2 preparation path, with other accepted frameworks acknowledged.
- Empty reuse inventories say not assessed. Reviewed mappings requiring FedRAMP-specific work, unreviewed mappings and requirements without reviewed support are separate.
- Reports use full question wording and disclose project catalog, guidance catalog, source URL, source verification date and pending qualified guidance review.
- The result offers optional organization/offering labels and a portable-backup reminder.
- Official rules are pinned to catalog 2026.11.02.01 at commit 64fa769510416fa75fd00a4689466094265b8083, verified November 6, 2026.
- The additional mandatory Class A list has 24 records, including SDR-CSX-KSI. CPO-CSF-CPM is no longer in the recommended set.
- All eleven official schemas were retrieved again on November 6. Their dated filenames did not change, but their versions and checksums did. Offline validators were regenerated.

## Dependency maintenance

Updated PDF.js, Zod and Next.js plus targeted transitive packages to address the production audit. The current high/critical release threshold must pass; lower-severity findings are disclosed in reports/release/dependency-audit.md. The release residue scan no longer uses the expired July worker exceptions.

## Existing projects

July catalog projects remain importable and exportable without a silent baseline rewrite. The catalog banner describes the update and offers backup navigation before explicit reconciliation. Reconciliation adds the new mandatory record, reopens current requirement and mapping reviews, and preserves narratives, historical records, generated outputs and frozen snapshots. Retired records do not create new action-plan tasks or new official requirement assertions. New package generation requires reconciliation.

Historical approvals are historical evidence, not approval of updated work. The changed project hash invalidates reuse of a previous final-review snapshot for current work.

## Release boundary

This is a public beta, not a claim that a provider is certified, approved or ready for submission. Mapping playbooks remain Draft. Qualified regulatory interpretation/package review, moderated customer study, manual accessibility and real-hardware testing remain external gates for 1.0.

The five-minute starting-plan objective is a usability target, not a measured customer result. The validation protocol is in CUSTOMER_VALUE_VALIDATION.md. Local automated checks are recorded separately from production hosting verification.
