# Test Flake Analysis

## Baseline

The prior release candidate timed out three full-application jsdom tests during grouped execution:

- `evidence-metadata.test.tsx` — `creates and edits a fully described evidence candidate`
- `evidence-metadata.test.tsx` — `hashes a normalized external reference and locks its hash identity`
- `package-freshness.test.tsx` — `retains the exact generated package bytes and binds a final snapshot to them`

The tests passed individually when given more time, but that was not accepted as evidence of stability. The package test had a targeted ten-second timeout and still took 5.61 seconds in a constrained run. The evidence tests and several other full-App flows approached or crossed Vitest's default five-second timeout when many jsdom files ran concurrently.

## Root cause

Two independent costs combined under grouped load:

1. Full-App tests rendered the large application shell, hydrated a sample project, initialized persistence and schemas, and cloned or validated the project on each input event.
2. Vitest ran several memory-heavy jsdom files concurrently. On constrained hosts this caused per-test delays and, under extreme host swap or disk pressure, fork-pool termination.

This was a test-architecture and resource-concurrency problem, not a product timer or an assertion that needed more time. No global or targeted test timeout was increased.

## Corrections

### Evidence workflow

`Evidence` now exposes the existing feature component as a narrow test seam. A stateful project-store harness exercises the production Evidence view and update recipe without booting the entire application shell. Long text and date fields use a single change event when per-character behavior is not under test; user events remain for selections, disclosures, relationships, submission, and edit activation.

The tests still verify persistence, hashing, immutable evidence identity, candidate status, and requirement and SOC 2 relationships.

### Package finalization workflow

The package snapshot test previously combined two independent concerns: retaining exact generated bytes and performing a complete project-backup export. Backup byte inclusion already has focused coverage in `backup.test.ts` and project-bundle tests. The full backup operation was removed from the snapshot test, date fields now use one change event, and the targeted ten-second timeout was removed. The retained-byte and immutable-snapshot assertions remain.

The corrected snapshot test completed in 0.098 seconds in the focused verification run; the full package-finalization file completed six tests in 1.21 seconds of test execution.

### Suite concurrency

`apps/bridge/vitest.config.ts` now uses one worker with file parallelism disabled. This is the tested release configuration for memory-heavy jsdom integration files and makes the normal `pnpm test` and source-archive verification commands use the same constrained behavior. CI repeats all affected files, the complete bridge suite, and the complete workspace suite without relying on Turbo cache.

## Verification evidence — 2026-07-18

Runtime: Node.js 24.18.0, pnpm 10.33.0, Vitest 4.1.10.

- Affected group, ten consecutive constrained runs: 120/120 tests passed across 30/30 file executions. Run durations were 4.41–4.78 seconds.
- Complete bridge suite, five consecutive constrained runs: 485/485 tests passed across 85/85 file executions. Durations were 32.81, 27.24, 21.86, 25.32, and 20.72 seconds.
- Normal bridge command after the configuration change: 97/97 tests passed across 17/17 files in 20.76 seconds.
- Complete workspace suite, three consecutive forced uncached runs: 1,047/1,047 tests passed across 138/138 file executions. Turbo completed 15/15 tasks each time in 33.911, 33.859, and 35.177 seconds.
- Complete bridge suite with shuffled order and seed `20260718`: 97/97 tests passed across 17/17 files in 20.62 seconds.
- Full workspace baseline: 349/349 tests passed across 46/46 files.
- Formatting, lint, and TypeScript checks passed after the changes.

One exploratory run was invalidated when another agent simultaneously ran a second full workspace verification while the host had less than 1 GB of disk and 24.5 GB of swap in use; Vitest reported an operating-system worker exit, not a test assertion or timeout. The concurrent process was stopped, the recoverable pnpm cache was pruned, and all consecutive results listed above were collected without competing release suites.

    tests/evidence-metadata.test.tsx \
    tests/package-freshness.test.tsx \
    tests/validation-navigation.test.tsx \
    --maxWorkers=1 --no-file-parallelism --reporter=dot

    --maxWorkers=1 --no-file-parallelism --reporter=dot

  TURBO_FORCE=true pnpm exec turbo run test --concurrency=1 --output-logs=errors-only

  --sequence.shuffle --sequence.seed=20260718 --reporter=dot
